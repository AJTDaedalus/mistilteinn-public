## T.3 — the per-character action vocabulary

**Done.** 55 of 117 characters carry a variant; `test_variant_params_are_classified` guards the rest.

**Files:** `backend/scripts/gcsim/build_key_snapshot.py`, `backend/app/data/gcsim/keys.json`,
`backend/app/services/gcsim_keys.py`, `backend/app/services/rotation_compiler.py`

gcsim generates a **parameter validation table** per character —
`internal/characters/<pkg>/zz_<key>.dm.go`, `paramsFor := map[action.Action][]string{…}`,
marked *"Code generated by pipeline; DO NOT EDIT"*. That is the authority for which params a
character accepts on which action, and it is the same kind of generated file the key snapshot
already parses.

- Snapshot **every** param verbatim as `character_action_params`. Faithful, not filtered.
- `gcsim_keys` decides which become offerable actions: `hold`, `short_hold`, `recast`.
  A test asserts every param in the snapshot is classified as offered or not-offered, so a
  re-pin that introduces a variant fails loudly instead of silently not offering it.
- The compiler renders `skill_hold` as `skill[hold=1]`. That table is the only place the
  parameter exists.

**Measured at the pin:** 117 generated files; 55 characters carry an offerable variant.
Dahlia and both Geo Travelers have `short_hold` and no `hold`, which is why `hold` alone
would have left them out.

**Acceptance:** the picker's per-character list equals what the validator accepts, per
character; a compiled `skill_hold` is accepted by real gcsim
(`npm run gcsim:verify-config`); `test_variant_params_are_classified` fails on an unclassified
param.

## What T.9 found

Both were invisible to a clean build, a green suite and a passing lint, and both were obvious
in a screenshot of the real page.

**The tap/hold badge rendered as nothing.** It was drawn `background: var(--accent); color:
var(--surface)`, and **there is no `--accent` in this palette.** An undefined custom property
invalidates the whole declaration at compute time, so the background disappeared and
`--surface` put dark text on a dark tile. The DOM had the badge; `timeline.spec.ts` asserted
its text and passed.

**Chevreuse's rows wrapped their buttons onto a second line, and nobody else's did.** A
`<select>` sizes itself to its longest option, and the longest option is now a real ability
name — *"Short-Range Rapid Interdiction Fire (hold)"*. So the list looked broken on exactly
the rows the kit variants are on.

`npm run check:tokens` (`frontend/scripts/check-css-tokens.mjs`, wired into CI) is the half a
machine can check. It found four more undefined tokens live in the tree today: the toast's
border and dismiss colour, a `--radius-sm` in two stylesheets, and `--space-5` in four — one
already written `var(--space-5, var(--space-4))`, so somebody had met it once and fixed only
their own file. That is `FINDINGS_frontend_validation.md`'s finding again: a pattern nothing
owned, so every page decided separately.
